# WHIQ changes to WordCraft

Branch `whiq` of the White Hat IQ fork of [storytold/wordcraft](https://github.com/storytold/wordcraft).
The platform runs `wordcraft-cli mcp` headless, one process per caller and document, behind a
supervisor, with the read/write roots set to the chat's folder and the author set to the caller.
The agents that call it run long and unattended, so the rule for every tool is **no dead stops**:
every limit is a recoverable answer, never a failure. This file lists every change, why, and how it
is tested. Upstream code is changed as little as possible (new modules carry the WHIQ work; touched
upstream lines are marked `WHIQ`), so upstream merges stay easy.

Build: `cargo build --release -p wordcraft-cli` (set `CRAFT_FONTS_DIR` to a checkout of
[storytold/craft-fonts](https://github.com/storytold/craft-fonts) at the release pin so the Arabic
fallback face is embedded). Tests: `cargo test`; the contract suite alone:
`cargo test -p wordcraft-cli --test mcp_contract`; end-to-end smoke of a built binary:
`tests/mcp-contract/smoke.sh [path/to/wordcraft-cli]`.

## 1. The shared MCP contract (craft-fork-contract.md §1–10)

| # | Change | Where | Tested by (`tests/mcp-contract/contract.rs` unless noted) |
|---|---|---|---|
| 1 | Every tool error is `{code, reason, next_step}` plus details (`closest`, `retry_after_ms`, `recovered`, `job_id`…), in `structuredContent.error` and as the text. Engine messages are classified: `unknown_tool`, `unknown_command` (closest ids), `bad_params` (what the tool takes), `not_found` (closest file names in the folder, or closest phrases for `select_text`), `path_refused`, `out_of_range`, `not_available`, `needs_app`, `needs_password`, `busy`, `evicted`, `internal`, `too_large`, `job_not_found`, `failed`. | 2 | Nothing hangs. `wordcraft-cli mcp` now serves through a runtime: a reader thread, a worker thread that owns the document, and a main thread that never waits on it. A call that needs the document while another runs answers `busy` with `retry_after_ms` (and the `job_id` when one runs). A call still running after `--job-after-ms` (default 15000) answers with a `job_id`; `background: true` makes any call a job at once; `job_status` reports `running` (elapsed, progress for batches) or the tool's own result, which is kept (the newest 64 jobs) so it survives client timeouts. A cancelled request becomes a job too. `initialize`, `ping`, `tools/list`, `resources/list`, `server_status` and `job_status` are answered by the main thread at any time. | `crates/mcp/src/runtime.rs` | `a_long_call_becomes_a_job_and_others_get_busy` (uses the `__sleep` test hook) |
| 3 | Work is never lost. The open document is published after every call; it is auto-saved to `<name>.recovered-<stamp>.docx` inside the write root (else the document's folder) on SIGTERM / SIGINT / SIGHUP (and console close on Windows, via `ctrlc`), when the client disconnects with unsaved changes, on a panic outside a command (answered `internal` with the path), on `close_document` with unsaved changes, and when memory passes `--max-memory-mb` (resident memory on Linux, the document's own size elsewhere: the document is closed after the call, the call's answer says so, and the next call answers `evicted`). A marker (`.wordcraft-recovered.json`) lets the next process on the same root answer `evicted` with the file and the step (`open_document` on it) on the first call that needs the document. The same state is never auto-saved twice. | `crates/mcp/src/recover.rs`, `runtime.rs`, `server.rs` | `sigterm_auto_saves_and_the_next_call_names_the_file`, `disconnecting_with_unsaved_work_auto_saves_it`, `a_panic_is_answered_and_the_work_auto_saved` (`__panic` hook), `memory_pressure_evicts_with_the_work_auto_saved` |
| 4 | Oversized results are trimmed: the result's largest list (or text) is cut to `--max-result-bytes` (default 100000; per call `max_bytes`) with `truncated: true`, `continue_from`, `total` and a `next_step`; passing `continue_from` back continues. Images: `render_page` keeps the PNG total under 16 MB, continuing with `continue_from` across a page range, and answers `too_large` with the largest DPI that fits for a single page. `server_status` reports version, pid, uptime, memory (resident, document estimate, limit), the open document (name, path, unsaved changes, paragraphs, words), the running call, jobs, recovered files, roots, author and limits. | `contract.rs` (`trim`), `whiq.rs`, `runtime.rs` (`status_json`) | `oversized_results_are_trimmed_with_continue_from`; unit tests in `contract.rs` |
| 5 | Forgiving inputs: tool names, command ids (in `execute` and `batch`) and argument names match case-insensitively and in either spelling (`SaveDocument`, `save-document`, `FORMAT_BOLD`, `keep_going`), short aliases (`open`, `save`, `status`…) resolve, numbers and booleans given as strings are read as such, and arguments outside the schema are dropped with a warning on a successful call. `select_text` falls back to a case-insensitive match (with a warning) and answers `not_found` with the closest phrases. | `contract.rs` (`normalise_args`, `unique_match`), `whiq.rs` | `inputs_are_forgiving_with_warnings` |
| 6 | Paths: confinement as upstream (`--automation-read-root` / `--automation-write-root`, links followed); relative paths now resolve inside the write root (the server runs in it). Every save stays atomic (temp + fsync + rename) and never silently replaces a file: under MCP the file a save would replace is first kept as `OLD_<name>` (`OLD_2_<name>`… when taken; a hard link, or a copy where links don't exist), and the response lists it (`kept_previous`) with a warning; `overwrite: true` replaces. This is an engine-level policy (`file_access::with_overwrite`) applied in `safe_save` just before the rename, so it covers every command that writes (save, export, print to PDF, PNG, templates, mail merge…). | `crates/engine/src/file_access.rs`, `crates/engine/src/io/safe_save.rs`, `apps/wordcraft-cli/src/main.rs` | `saves_are_confined_atomic_and_never_silently_overwrite`; `safe_save::keep_old_keeps_the_replaced_file_beside_the_new_one` (engine) |
| 7 | Caller identity: `--author NAME` at start (upstream) and an optional `caller` argument on every tool: tracked changes, comments and the saved document's last-modified-by carry it for that call; the default comes back after. | `whiq.rs` (`call_tool`) | `tracked_changes_and_comments_carry_the_caller` |
| 8 | Annotations: `readOnlyHint` only on reads (`list_commands`, `get_text`, `inspect_document`, `render_page`, `parity`, `screenshot`, `ui_inspect`, `server_status`, `job_status`), `destructiveHint` on every tool that can delete or overwrite (editing tools, saves and exports, opening or starting a document, which replaces the open one), `idempotentHint` where true. Every result carries `structuredContent` (an object; other values under `result`). | `whiq.rs` (`tool_definitions`) | `annotations_say_what_each_tool_does` |
| 9 | `tests/mcp-contract/`: `contract.rs` drives the built binary over stdio (registered as the `mcp_contract` test of `wordcraft-cli`, so `cargo test` builds and runs it; `WORDCRAFT_CLI` tests another binary), `client/` is its MCP client, `smoke.sh` runs a built binary end to end. Test hooks `__sleep` and `__panic` exist only with `WORDCRAFT_MCP_TEST_HOOKS=1`. | `tests/mcp-contract/` | `cargo test -p wordcraft-cli --test mcp_contract`, `tests/mcp-contract/smoke.sh` |
| 10 | Bidi/Arabic: upstream already makes a paragraph right to left when its first letters are Arabic or Hebrew and nothing sets its direction, and shapes and joins Arabic in layout, PNG and PDF (fonts embedded as subsets). WHIQ: `type_text` with `paragraphs: true` gives each new line the direction of its first strong character (an English line after an Arabic one is left to right, rather than inheriting the previous paragraph's direction); release builds (`CRAFT_FONTS_REQUIRED`) now fail without an Arabic face in craft-fonts, so the Arabic fallback font is always in the binary. | `whiq.rs` (`type_text`), `crates/fonts/build.rs` | `arabic_paragraphs_are_right_to_left_and_exported_with_embedded_fonts` |

New tools: `server_status`, `job_status`, `export_pdf` (path, page range, markup), `close_document`
(auto-saves unsaved changes unless `discard: true`), and `render_page` gains `pages` (a range),
`dpi` and `markup`. New `wordcraft-cli mcp` flags: `--job-after-ms`, `--max-result-bytes`,
`--max-memory-mb`. New dependency: `ctrlc` 3.4 (MIT/Apache-2.0) in `wordcraft-mcp`.

Limits worth knowing: `OLD_` keeping, auto-save and memory eviction apply to the headless server
(`--connect` drives the desktop app, which has its own saving and recovery). On Windows a
supervisor that kills the process outright (TerminateProcess) can't be caught; Ctrl+C, Ctrl+Break
and closing the console are.

## 2. Lossless round trip of a customer's document

Before: unknown elements in `word/document.xml`, headers, footers, notes and comments were
dropped on open (`_ => {}` in the readers), wrappers without a model (`w:customXml`,
`w:smartTag`, `w:bdo`, `w:dir`) were unwrapped, unmodelled run, paragraph and section properties
(`w14:ligatures`, `w:divId`, `w:cnfStyle`, `w:paperSrc`, `w:printerSettings`…) were lost, only one
branch of an `mc:AlternateContent` was kept (a shape lost its VML fallback, a 3-D model became its
picture), and parts referenced only from such markup were dropped with it.

| Change | Where | Tested by |
|---|---|---|
| Namespaces no reader knows are named by a hash of their URI (`?hhhhhhhh:`) instead of collapsing to `?:`, so their markup can be written back; `El::to_xml_ext` writes them with the prefix `xhhhhhhhh` declared on the element, and `mc:Choice/@Requires` likewise. The writer hoists those declarations to each part's root and lists the prefixes in its `mc:Ignorable` (Word skips what it doesn't know). | `crates/docx/src/xml.rs`, `write/passthrough.rs` (`hoist_namespaces`) | unit tests in `xml.rs`, `write/passthrough.rs` |
| Opaque pass-through nodes, in order (`InlineObject::Opaque` gains `refs`, its relationships): an unknown block-level element becomes a `docx-block` object written before the next paragraph (or after the story's last); unknown elements among runs and inside runs become `docx` objects; wrappers keep their start/end tags (`docx-open`/`docx-close`, `docx-block-open`/`docx-block-close`), written balanced (a tag whose partner was edited away is left out; wrappers never cross a content control or hyperlink). Parts their relationships reach are carried (`keep_part_tree`), with relationships renumbered on write. | `crates/docx/src/read/passthrough.rs`, `read/story.rs`, `write/passthrough.rs`, `write/story.rs`, `crates/doc/src/para.rs` | `crates/docx/tests/corpus_roundtrip.rs` |
| Unmodelled properties kept as markup: `CharProps::ext_xml` (run properties, also in styles), `ParaProps::ext_xml` (written last in `w:pPr`, where CT_PPrBase puts `w:divId`/`w:cnfStyle`), `SectionProps::ext` (with relationships: `w:printerSettings`), written at their schema positions (`w:paperSrc` after `w:pgMar`, `w:noEndnote` after `w:vAlign`, `w:rtlGutter` after `w:bidi`, the rest last). | `crates/doc/src/props.rs`, `section.rs`, `crates/docx/src/read/props.rs`, `write/props.rs`, `write/story.rs` | `corpus_roundtrip.rs`; `every_char_prop_round_trips`, `every_para_prop_round_trips` (`crates/docx/tests/roundtrip.rs`, extended) |
| `mc:AlternateContent` at run level: the object read from the chosen branch is fingerprinted; the whole `AlternateContent` (every branch, with its parts) is kept under that fingerprint, and an object still unchanged at save time (text box text included) is written back with every branch (fresh drawing ids, relationships renumbered). An edited object is written from the model. | `read/story.rs`, `read/passthrough.rs` (`keep_alternate`), `write/passthrough.rs` (`fingerprint`, `kept_alternate`) | `corpus_roundtrip.rs` (`w14-future-markup.docx`, `model-3d.docx`) |
| The round-trip diff tool: part lists (a part saved under another name with identical bytes counts as renamed), every part's relationships (by type and target), binary parts byte for byte, and the story parts as a namespace-expanded normalised tree (rsids, `w14:paraId`/`textId`, proofing marks and empty property containers left out): an element inventory (anything fewer after the save is a loss; a field counts the same as `w:fldSimple` or `w:fldChar`), the paragraph texts, and the first differing line. `wordcraft-cli roundtrip-check FILE [--save OUT]` runs it on any file (exit 1 when something is lost); the MCP tool `roundtrip_check` does too. | `crates/docx/src/roundtrip.rs`, `apps/wordcraft-cli/src/main.rs`, `crates/mcp/src/whiq.rs` | `corpus_roundtrip.rs` (`the_diff_tool_reports_dropped_parts_relationships_and_elements`), unit tests |
| The corpus: ten hand-written packages (from ECMA-376 and [MS-DOCX], no file produced by Word): tracked insertions/deletions/formatting/paragraph marks with a move and a comment; SmartArt (data, layout, quick style, colours, drawing); a chart with its workbook; custom XML (block, inline, data-bound content control, custom XML part); `w14` run effects and ligatures, a `w14` check box, a `wps` shape with its VML fallback, `w:bdo`/`w:dir`, proofing marks and markup in an ignorable future namespace (block, inline, in a run); an OLE object with its preview; a 3-D model with its picture fallback; header/footer with fields and future markup, footnotes with `w14` run properties; a macro project (`.docm`); `w:altChunk` with its part, `w:divId`, `w:cnfStyle`, custom XML in a table cell, `w:paperSrc`/`w:rtlGutter`/`w:printerSettings`. Open + save of each keeps every part and relationship and drops no element, saving twice is stable, and through MCP (open_document, save_document, and after an edit elsewhere) the same holds. Written to `target/whiq-corpus/` (`$WHIQ_CORPUS_DIR`) with the saved copies, to open in Word. | `crates/docx/tests/corpus/mod.rs` | `corpus_roundtrip.rs`; `every_corpus_document_survives_open_and_save_through_mcp` (contract suite) |

Behaviour changes upstream tests pinned (updated, marked WHIQ): the smart tag's and custom XML's
tags now precede a content control's start marker (`fixtures.rs::hyperlink_runs_and_wrappers`);
an unknown element that refers to a part keeps the part (`passthrough.rs::parts_the_writer_owns_or_the_body_refers_to_are_not_carried`).

Not covered: `w:customXml` directly around a table (it is unwrapped, as before; Word 2010 and
later strip custom XML markup themselves); unknown *attributes* on modelled elements (e.g.
`w16du:dateUtc` on `w:ins`) are regenerated, not kept; a block-level `mc:AlternateContent` keeps
its chosen branch only; objects inside an unknown element are not editable (they ride along as
markup).
